**Практична робота №7**

**Проєктування структури програмного забезпечення**

**Мета**

Сформувати розуміння структури майбутнього програмного продукту, його основних компонентів та взаємодії між ними.

**1\. Основні компоненти системи**

Проєкт Budget & Expense Tracker складається з трьох основних компонентів:

1. **Frontend** — інтерфейс користувача, створений за допомогою React. Відповідає за відображення інформації, введення доходів і витрат, навігацію та графіки.
2. **Backend** — сервер на Node.js та Express.js. Обробляє запити, перевіряє дані, виконує бізнес-логіку та забезпечує авторизацію.
3. **База даних** — SQLite. Зберігає інформацію про користувачів і фінансові операції. Для роботи з нею використовується Prisma.

**2\. Основні сутності та класи**

- **User** — користувач системи.
- **Transaction** — фінансова операція.
- **Category** — категорія доходу або витрати.
- **AuthService** — відповідає за реєстрацію, вхід та перевірку авторизації.
- **TransactionService** — виконує операції з доходами й витратами.
- **StatisticsService** — розраховує загальні суми та статистику за періодами.

**3\. Зв'язки між класами**

Один користувач може мати багато фінансових операцій. Кожна операція належить певному користувачеві та має категорію. Одна категорія може використовуватися в багатьох операціях. Сервіс операцій працює з даними транзакцій, а сервіс статистики використовує ці дані для розрахунків.

**4\. Спрощена Class Diagram**

Код діаграми мовою PlantUML:

class User {

+id: Int

+name: String

+email: String

+passwordHash: String

}

class Transaction {

+id: Int

+amount: Decimal

+type: String

+date: DateTime

+description: String

}

class Category {

+id: Int

+name: String

+type: String

}

class AuthService {

+login()

+verifyToken()

}

class TransactionService {

+createTransaction()

+updateTransaction()

+deleteTransaction()

+getTransactions()

+getBalance()

+getMonthlyStatistics()

}

User "1" -- "0..\*" Transaction

Category "1" -- "0..\*" Transaction

AuthService ..> User

TransactionService ..> Transaction

StatisticsService ..> Transaction

**5\. Обґрунтування проєктних рішень**

Система поділена на компоненти, кожен із яких виконує окремі завдання. Це полегшує розробку, тестування та подальше розширення програми. Наприклад, статистику можна вдосконалювати незалежно від інтерфейсу введення операцій. Зв'язки між користувачами, категоріями та транзакціями допомагають організувати зберігання фінансових даних.

**Висновок**

У ході практичної роботи визначено основні компоненти, сутності, класи та зв'язки між ними. Створена Class Diagram відображає базову структуру Budget & Expense Tracker і може використовуватися під час реалізації програмного продукту.
