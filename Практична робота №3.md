**Практична робота №3**

**Життєвий цикл програмного забезпечення**

**Мета роботи**

Ознайомитися з моделями життєвого циклу програмного забезпечення та обрати модель, яка найкраще відповідає особливостям проєкту Budget & Expense Tracker.

**1\. Основні моделі життєвого циклу**

**Каскадна модель (Waterfall).** Розробка відбувається послідовно: кожен етап завершується перед початком наступного. Підходить для проєктів зі стабільними вимогами.

**Ітераційна модель.** Продукт розробляється поступово, невеликими циклами. Після кожної ітерації можна перевірити результат і вдосконалити систему.

**Agile.** Гнучкий підхід, що передбачає короткі цикли розробки, регулярний зворотний зв'язок і можливість змінювати вимоги.

**2\. Порівняння моделей**

| **Критерій**                      | **Waterfall**        | **Ітераційна**    | **Agile**            |
| --------------------------------- | -------------------- | ----------------- | -------------------- |
| Послідовність                     | Послідовна           | Повторювані цикли | Гнучкі цикли         |
| Зміна вимог                       | Ускладнена           | Можлива           | Передбачена підходом |
| Зворотний зв'язок                 | Переважно наприкінці | Після ітерацій    | Регулярний           |
| Зручність для навчального проєкту | Середня              | Висока            | Висока               |

**3\. Обрана модель**

Для Budget & Expense Tracker обрано **ітераційну модель розробки**.

Вона дозволяє створювати продукт поступово, перевіряти кожну реалізовану частину та виправляти недоліки до завершення всього проєкту.

**4\. Етапи життєвого циклу**

1. Аналіз вимог — визначення функцій і потреб користувачів.
2. Проєктування — розробка структури системи, інтерфейсу та бази даних.
3. Реалізація — створення frontend, backend та інтеграція бази даних.
4. Тестування — перевірка правильності роботи функцій.
5. Впровадження — підготовка та розгортання готового продукту.
6. Супровід — виправлення помилок і вдосконалення системи.

**5\. Схема життєвого циклу**

Аналіз вимог → Проєктування → Реалізація → Тестування → Впровадження → Супровід

Після тестування за потреби відбувається повернення до проєктування або реалізації. Цикл повторюється для вдосконалення продукту.

**6\. Обґрунтування вибору**

Ітераційна модель підходить для навчального проєкту, оскільки команда складається з трьох учасників, а продукт має декілька окремих функціональних частин. Спочатку можна реалізувати авторизацію та облік транзакцій, а потім додати фільтрацію, статистику й діаграми.

**Висновок:** розглянуто основні моделі життєвого циклу, порівняно їхні особливості та обрано ітераційну модель для розробки Budget & Expense Tracker.
